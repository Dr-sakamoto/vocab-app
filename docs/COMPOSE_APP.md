# 瞬間英作文（`/compose`）— 設計メモ

同じリポジトリに入っている2つ目のアプリ。単語アプリ（`/`・`/result`）とは
**別のコアループ・別の学習状態**を持ち、コードもデータも共有しない
（共有しているのはデザイントークン、AI判定の作法、分散学習の間隔、
レート制限、localStorage ラッパなどの基盤だけ）。

## なぜ別のアプリなのか

単語アプリのコアバリューは「フロー状態」で、1問ごとの割り込みを徹底的に
排除する設計になっている。英作文はそこが違う。

| | 単語（`/`） | 英作文（`/compose`） |
| --- | --- | --- |
| 1問の負荷 | 低い（訳語を1語思い出す） | 高い（文を組み立てる） |
| 1セット | 10問 | 3〜8問（既定5問） |
| 学びが起きる場所 | 出題を繰り返すこと自体 | **添削を読む瞬間** |
| 正誤の見せ方 | 10問まとめて | 1問ずつ、専用フェーズで読ませる |
| 出題の狙い | 語の定着（ドーナツの分布） | **文法・表現の弱点** |

英作文で「10問打ち切るまで何も見せない」をやると、学びの核心である添削が
最後にまとめて5枚届くことになり、読み切れない。逆に「1問ごとに採点を待つ」
をやると、AI採点1件あたり10秒前後の待ちがセッションに5回入る。

## コアループ

```
start   … 弱点を見て、モード（英作文 / 弱点特訓 / 英文和訳）と問題数を選ぶ
  ↓
writing … 5問を続けて書く。確定した答案はその場で裏の採点へ回り、
          次の問題を書く時間と並走する（＝待ち時間がループから消える）
  ↓
review  … 全部書き終えてから、1問ずつ添削を読む。ここは削らない。
          採点が返るまでは次へ進めない（読まずに飛ばせない）
  ↓
summary … タグ（文法）ごとの習熟度がどう動いたかを見せる
```

「採点を待たずに次を書く」は単語アプリの小テストから借りた形。違うのは、
読む時間を削るのではなく **専用のフェーズとして確保している** ところ。

## 弱点分析

- 出題データ（`lib/compose/prompts/`）は1問ごとに「何を試しているか」を
  文法タグ（`lib/compose/grammarTags.ts`、21種）で宣言する
- AI採点はタグごとに `ok` / `shaky` / `missed` を返す。返ってきたIDは
  必ずタグ表と突き合わせて絞る（AIが作った架空のタグを統計に入れない）
- タグの習熟度は直近を重く見た平均（EMA, α=0.4）に、答案が少ないタグを
  中庸へ引き戻す縮小推定を掛けたもの（`lib/compose/mastery.ts`）
- 出題の重みは「タグの弱さ × その問題の復習どき × レベルの当たりぐあい」。
  時間の効かせ方は単語アプリの分散学習（`lib/reviewSchedule.ts`）を流用
- 1セッションで同じタグは2問まで。弱点に寄せるほど偏るが、5問すべてが
  同じ弱点だと「今日は何もできなかった」という記憶だけが残る

## 採点

`POST /api/compose/check` の1往復で確定する。

1. 設問・模範解答・狙いのタグは **`promptId` からサーバー側で引く**。
   クライアントから受け取らないので、出題データを偽装して満点を取ることも、
   タグを詐称して弱点統計を汚すこともできない
2. Gemini（`gemini-2.5-flash`, temperature 0）に採点させ、
   スコア・添削文・指摘・できていた点・タグごとの判定をJSONで受ける
3. AIが使えない（キー未設定・レート制限・応答不正・通信失敗）ときは
   模範解答との照合で採点する（`lib/compose/localGrade.ts`）。
   待たせた末に「採点できませんでした」を返さない

## 学習状態の保存

いまは端末（localStorage）だけ。キーは `compose-progress` /
`compose-settings` / `compose-daily-streak`。

クラウド同期（Supabase）は**まだ載せていない**。単語アプリで
「列を足すコードだけ先に出て、本番への `db push` を忘れて同期が止まる」
事故が実際に起きているため、まず端末で完結させ、同期は別PRで足す。
保存形は読み込み時にすべて正規化しているので（`lib/compose/progress.ts`）、
あとから同期を足しても壊れた値が入り込まない。

## 出題データを足すには

`lib/compose/prompts/{basic,standard,advanced}.ts` に追記する。

```ts
{
  id: "b31",                        // 統計の保存キー。公開後は変えない
  ja: "彼はもう宿題を終えました。",
  answers: ["He has already finished his homework."],  // 先頭が主たる解答
  tags: ["perfect"],                // grammarTags.ts のIDだけ
  level: 1,
  note: "already は have と過去分詞の間に置く。",       // 採点後に必ず添える一言
}
```

`tests/composeDeck.test.mjs` が、IDの重複・未定義タグ・タグごとの問題数
（3問以上）・和文と英文の取り違えを見張る。データを足したら `npm test`。
